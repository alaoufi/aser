# Jdatna phase-one implementation plan

Goal: implement the approved Arabic producer marketplace and prepare isolated Coolify operations.
Architecture: Next.js App Router, TypeScript, PostgreSQL and server-side role enforcement.
Spec: docs/superpowers/specs/2026-11-08-platform-design.md and docs/REQUIREMENTS.ar.md.

## Global constraints
No fictional production listings. No electronic payments. No access to Aykdmh data.
Registration is closed in production until real OTP and private object storage pass.
Arabic RTL, accessible mobile UI. Coolify integration follows application verification.
Latest user instruction also requests organizing existing public sites in Coolify;
audit and reversible migration are required; no automatic performance claims.

## Review focus
Unauthorized producer ownership; private document disclosure; unapproved listings;
contact-price treated as zero; runtime schema/admin privileges.

## Task 1 — Application and public catalogue
- [ ] Set up package/build configuration and common typed catalogue contract.
- [ ] Add home, filtered browse, family/product pages and real empty states.
- [ ] Add static legal/about content and accessible responsive navigation.
- [ ] Verify typecheck, production build and mobile/browser navigation.

Interfaces: src/lib/types.ts defines Category, City, Producer, Product and Filters.
src/server/catalog.ts exports getCategories(), getCities(), searchProducts(filters),
searchProducers(filters), getProducer(slug), getProduct(id), returning those types.

## Task 2 — PostgreSQL, authentication and management
- [ ] Write meaningful tests for validation, session security and ownership failures.
- [ ] Add additive migration and migration script, catalogue and bounded search queries.
- [ ] Add cookie sessions, OTP provider adapter (production fail-closed), CSRF/rate limits.
- [ ] Implement producer application, product CRUD and administrator review API.
- [ ] Add S3-compatible encrypted private storage adapter with unconfigured fail-closed.
- [ ] Verify unit/integration tests in isolated scratch database and migrations.

Files: src/server/**, migrations/**, scripts/**, tests/**, src/app/api/**.
Auth interface: GET /api/session, POST /api/auth/request-otp and verify-otp;
POST /api/logout. APIs return {error:string} on failure without internal details.
GET/POST /api/producer/profile; GET/POST/PATCH /api/producer/products;
GET /api/admin/producers; POST /api/admin/producers/[id]/review.

## Task 3 — Forms and dashboards
- [ ] Build login/OTP, family registration, producer profile/products and admin review UI.
- [ ] Surface API errors, real readiness state and access-denied states.
- [ ] Verify auth/role gates, validation, keyboard/mobile behavior and safe links.

Files: src/components/forms/** and src/app/(account)/** only.

## Task 4 — Deployment and operational integration
- [ ] Dockerfile, health endpoint, isolated runtime secrets and rollout/rollback runbook.
- [ ] Inspect Coolify public-site inventory and current routing without reading customer data.
- [ ] Verify backup and deploy Jdatna only when release gates pass; otherwise keep holding page.
- [ ] Prepare and execute reversible Coolify organization of authorized public sites,
      retaining current proxy/database/storage ownership unless tested migration requires more.
- [ ] Whole-branch review, tests/build, documentation and task commits.
