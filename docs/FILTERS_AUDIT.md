# فحص الفلاتر الشامل — 2026-11-25 (الإصدار 9.0.3.0)

طلب المالك: فحص شامل وعميق لكل فلاتر الموقع بـ Playwright، ومطابقة النتائج مع البيانات الفعلية، وإصلاح الأسباب الجذرية، وربط الاختبارات بـ GitHub Actions.

## البيئة والأمان

- Playwright 1.65 موجود في المشروع (لم يلزم تثبيت). Chromium مثبّت في بيئة الفحص.
- كل الاختبارات على قاعدة اختبار معزولة اسمها يبدأ بـ `jdatna_test_`، ويتحقق كل اختبار من ذلك قبل أي كتابة، ويحذف بياناته بعده. لا شيء على بيانات الإنتاج.
- نقطة التراجع: الفرع `backup/before-filters-audit` (65ced7a)، قبل أي تعديل.

## الاختبارات المضافة

1. **`tests/filters.test.ts`** (قاعدة البيانات): يزرع 4 أسر ظاهرة و3 لا يجوز أن تظهر (بانتظار الاعتماد، أسرة مراجعة المتاجر، موقوفة)، وأقسامًا بأب وابن، و~110 منتجات بكل الحالات ونطاقات التوصيل، ومنها منتج محذوف ومنتج مخفي. يحسب النتيجة المتوقعة بمنطق مستقل ويطابقها مع دوال الموقع في **277 تركيبة**: كل فلتر منفردًا بكل قيمه، وكل زوج فلاتر بكل قيمهما، وتركيبات ثلاثية ورباعية. لكل تركيبة يمر على كل الصفحات ويتحقق من عدم التكرار والاكتمال، ويقيس الزمن. ويفحص أيضًا: الترقيم (30 و60 منتجًا بوقت إنشاء واحد)، والأسر بالمنطقة والمدينة والقسم الأب، و«مائدة اليوم» (المتاح فقط وليس من أسرة لا تطبخ اليوم)، والتصفح بالمنطقة مع «يُشحن لكل المناطق» بلا تكرار بين القسمين.
2. **`tests/e2e/filters.spec.ts`** (المتصفح، كمبيوتر وجوال وتابلت): يزرع 35 منتجًا، ويتحقق مما **يُعرض للمستخدم** مقابل القاعدة: كل المطابق يصل عبر الصفحات بلا تكرار، والعدد الظاهر هو الكامل؛ القسم الأب يشمل ابنه؛ المنطقة ومعها القسم؛ التبديل السريع المتتابع بين أربعة فلاتر ينتهي بنتيجة آخر فلتر فقط؛ زمن التحميل.
3. **GitHub Actions**: مهمة جديدة «اختبارات قاعدة البيانات والفلاتر» بقاعدة PostgreSQL 16 مؤقتة لكل تشغيل، تشغّل `npm test` كاملًا بقاعدة البيانات، ثم `filters.spec.ts` في المتصفح.
